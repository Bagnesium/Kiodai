## Findings — ready to paste

The first exploratory pilot produced one usable A0/A1 pair with TP=5, FP=0, FN=0 and Set-F1=1.00 in both conditions. A separately frozen three-day follow-up produced one further paired trajectory, with TP=11, FP=0, FN=1, precision=1.00, recall=0.9167 and Set-F1=0.9565 in both conditions. Thus neither study showed an observed accuracy improvement from the frozen P1 instruction. The follow-up was planned after inspecting the pilot and includes its Monday segment, so these observations are not pooled as independent evidence. A1 consumed 9,800 additional input tokens in the follow-up. Saved API responses reported a combined cost of $0.03047594; independently verified billing was unavailable.

The hidden-condition failure can be localized behaviorally but not assigned an internal cognitive cause. Both agents received the instruction to acknowledge fully stable cooling. At Tuesday 11:30, A0 queried the sensor board and received a negative reading; A1 made no query. At 13:00, the visible scene stated that the review window opened while cooling continued out of sight. Neither requested the positive hidden reading, and both omitted the cooling acknowledgement. The complete original instruction remained in the history. This supports an observed failure to obtain the relevant positive evidence and execute the intention, not proof that the model forgot, misunderstood, or guessed. Both later cross-day actions succeeded with full history available.

Kiodai v2 is a separately implemented PIS-inspired system, not a modification of the historical prompt-only A1 condition. It combines a cited typed intention store, versioned updates, bounded channel polling and execution-receipt lifecycle checks. The B_ledger comparator shares its extraction, storage and action-selection logic while leaving query decisions to the model. A0 retains prompt-only reasoning. Internal model calls are counted in every method, so this comparison is not compute-matched.

Local software verification exercised 12 synthetic development trajectories across four template families. All three methods' explicitly mocked language fixtures reached the same task outcomes. These fixtures establish that the implementation can carry valid intentions through querying, selection, execution and scoring; they do not demonstrate reliable extraction or an accuracy advantage in a real model. A cooling-only mock regression over the intact original 20-step story obtained the later positive reading and selected the cooling acknowledgement; its remaining task misses are retained because that fixture intentionally supplies no semantics for other tasks.

One real local development attempt used the already installed `llama3.2:latest` model through Ollama on loopback. It completed only one of eight decision points. Four extraction requests produced two invalid source-citation outputs, one truncated malformed JSON output at the output-token limit, and one timeout. No primary trajectory score or comparative conclusion is available. The saved three responses report 2,618 input and 3,883 output tokens in total; the timed-out request's usage is unknown, so full-run totals remain unavailable. This local attempt incurred no paid API inference.

A subsequent, separately authorized A2 development smoke used frozen DeepSeek V3.1 through Novita on one complete exposed hidden-state scenario. All eight checkpoints completed, with TP=0, FP=0, FN=2, undefined precision, recall=0 and Set-F1=0. Three instructed obligations remained uncompleted: the dependent sealing task never became due because registration failed, so it did not add an official false negative. Fourteen extraction responses conformed to the emitted JSON schema, but six failed additional application validation and the eight accepted responses contained empty operation lists. No intentions were stored, no hidden-channel query occurred, and no task action or execution receipt followed. There were 24 model calls, eight retries, 57,052 input tokens and 4,380 output tokens. Saved API responses reported $0.01525668; independent billing verification remains unavailable. This is usable negative development evidence, not successful integration or a comparison with A0 or B_ledger. The full 12-trajectory comparison remains unlaunched.

## Discussion and limitations — ready to paste

The contribution is an engineering integration and a testable monitoring ablation, rather than a claim to have invented typed agent memory. PIS supplies the main architectural precedent; PM-Bench supplies the unchanged environment and scorer; TriggerBench motivates separating prospective action from retrospective access and retaining negative controls. The proposed benefit of deterministic monitoring remains unproven. The local Llama attempt demonstrates that structured extraction itself can fail, and the system must account for those failures instead of conditioning headline results on successful extraction.

The system validates cited spans, versions and execution states mechanically. It cannot guarantee the correctness of natural-language extraction, action binding, dependency interpretation or evidence relevance. Quarantining an ambiguous update can also block legitimate actions. A2's policy is simple bounded polling; no efficiency advantage over ordinary periodic polling is claimed. The primary synthetic suite contains only four template families, uses full history and has been inspected by the same implementation process. It is exploratory and cannot establish broad superiority, general equivalence, intrinsic memory improvement or performance on an independently held-out benchmark.

The DeepSeek smoke revealed a contract gap: empty condition strings satisfy the emitted schema but fail the application's nonempty-condition rule. The generic corrective message did not recover a populated ledger. Separately, two rejected drafts treated a cited menu distractor as an instruction. Real quotation spans therefore did not establish correct interpretation. The evaluated implementation was left unchanged throughout the run; no paid repair cycle followed. The observed absence of premature actions cannot be attributed to negative hidden evidence, because the agent never queried that evidence. Likewise, the smoke did not exercise successful receipt-based completion. These failures limit claims about this frozen integration without establishing an intrinsic limitation of the underlying model.

Frozen P1 still assumes completion after selection. PM-Bench removes completed handles, so its task scores cannot independently establish prompt-driven duplicate prevention. Local receipt/idempotency tests concern only a SQLite simulator, not external exactly-once execution. Heartbeat and background calls are disabled. The historical follow-up contains one paired trajectory; v2 has one completed paid A2-only development trajectory and no paid comparative matrix. These studies are kept separate. The interrupted local smoke began before the final implementation freeze; raw requests and responses preserve its actual inference inputs, while a separately labeled recovery manifest records post-hoc artifact finalization after a reporting bug was fixed. No failed response was replaced with a mock.

## Простое объяснение для статьи

В исходных экспериментах дополнительная инструкция P1 не повысила Set-F1. Программные механизмы Kiodai v2 проверены на имитационных ответах, но реальный проверочный запуск DeepSeek выявил проблему интеграции: восемь шагов завершились без сохранённых намерений, запросов к скрытому каналу и выполненных задач. JSON-схема и дополнительные требования программы оказались недостаточно согласованы; также возникли ошибки понимания инструкций. Это отрицательный результат одной открытой проверочной истории, а не доказательство надёжной памяти или сравнение методов. Полный сравнительный эксперимент не запускался.

## Защита: примерно 60–90 секунд

Мой проект исследует, может ли языковая модель выполнить поручение позже, когда появится нужное условие. Например, нужно подтвердить охлаждение, но сначала проверить показания датчика.

В первой версии я сравнил обычного агента и того же агента с дополнительной инструкцией. Результат оказался одинаковым. В трёхдневной проверке обе версии правильно выбрали одиннадцать действий и пропустили одно. Дополнительная инструкция потребовала больше входных токенов. Поэтому я не утверждаю, что она улучшила память модели.

Во второй версии я реализовал список намерений с версиями и проверку разрешённых каналов. По замыслу завершение должно фиксироваться после подтверждения симулятора. Архитектура опирается на существующие исследования, а программные механизмы проверены на имитационных ответах.

Настоящий проверочный запуск DeepSeek прошёл восемь шагов, но не сохранил намерения и не выполнил задачи. Часть ответов соответствовала JSON-схеме, но нарушала дополнительные требования программы; принятые ответы были пустыми. Кроме того, модель дважды приняла пункт меню за поручение. Все ошибки сохранены. Стоимость по ответам API составила около полутора центов. Поэтому мой вывод: программная схема реализована, но этот запуск выявил её неработающую интеграцию с моделью. Надёжность памяти и преимущество метода не доказаны. Полное сравнение не запускалось.
