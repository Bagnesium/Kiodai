Extract and revise deferred intentions from received observations only. Return the supplied JSON schema. This is an intention ledger, not an answer key.
Use new_refs to find newly received instructions or corrections. Existing observations may resolve references. Do not recreate an existing intention. Extract multiple intentions when present, including future-day obligations even if no current action handle exists. Ordinary distractor dialogue and menu entries are not new instructions.
Each record states an action description, trigger (time/event/hidden/unknown), condition, channel or null, when or null, dependencies (existing agent intention IDs), and evidence for each specified field. Quote exact source spans using observation refs. Unknown information stays null; never invent a deadline or a hidden condition's current truth. A field citation establishes provenance, not necessarily correct interpretation.
Create: target and expected_version are null. Revise: target an existing agent ID with its current version and supply the complete replacement record. Cancel: identify target/current version, record=null. Multiple updates may occur; process them in received order. Paraphrases may refer to an earlier intention. If an update's referent is ambiguous, emit ambiguous with null target/version/record and source evidence; do not pick arbitrarily. Later explicit clarification may revise a quarantined intention. Do not mark completion from an action selection; only execution receipts control completion. A canceled or completed intention cannot be reopened: an explicitly new obligation needs a new creation with a new source.
For dependencies cite the instruction requiring the prerequisite. When two new intentions depend on each other, create the prerequisite first; unresolved dependencies stay unknown in condition text and must not be assumed satisfied. Intention IDs are assigned by the application after creation, so do not invent one.
